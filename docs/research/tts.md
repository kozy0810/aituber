# TTS(音声合成)の調査結果

調査日: 2026-09-18
ステータス: **一次情報ベース。実機ベンチマークは未実施**

## 要件が緩和された経緯

当初は「リップシンクのために音素・ビセームデータを出力できること」をTTSの必須条件としていた。

しかしモデル生成の調査で、生成メッシュに口の開口部が存在しないことが判明し、リップシンクは**headボーンに親子付けした板を音声振幅で動かす方式**に決まった(`3d-model-generation-tools.md` を参照)。

**この結果、TTSに必要なのは「音声の振幅が取れること」だけになった。** 振幅はどんな音声データからでも算出できるため、事実上すべてのTTSが候補になる。選定は音質・コスト・日本語品質で行える。

## 決定的な論点: 24時間稼働の経済性

この配信システムは**キャラクターが24時間喋り続ける**。従量課金のTTSとは相性が悪い。

日本語の自然な発話速度を約300文字/分とすると、連続発話で月間およそ1,300万文字。実際には間や無音があるため、稼働率60%で約780万文字と見積もる。

| 選択肢 | 単価 | 月額(稼働率60%・約780万文字) |
|---|---|---|
| ElevenLabs(上位音声) | $0.09/分 | **約$2,300** |
| OpenAI gpt-4o-mini-tts | $0.015/分 | 約$390 |
| Google Chirp 3 HD | $30/1M文字 | 約$234 |
| Google Neural2 | $16/1M文字 | 約$125 |
| Google Standard | $4/1M文字 | 約$31 |
| **セルフホスト** | — | **実質$0(既存サーバーに同居)** |

**セルフホストが有利な理由は、レンダリング用のサーバーがどのみち必要だから。** TTSを同じマシンに載せれば追加費用はほぼ発生しない。しかもレンダリングはGPUを使い、AivisSpeechはCPUでも高速に動くため、**GPUとCPUで役割を分ければリソースが競合しない**。

一方、Google Standard の月$31 程度ならクラウドも非現実的ではない。運用の手間を省きたい場合の選択肢として残る。

## 候補の比較

### 日本語品質

- ローカルOSSでは **Style-Bert-VITS2 系(AivisSpeechが採用)が日本語品質で最高評価**
- クラウドAPIの日本語品質は僅差: Amazon Polly 91.3 / OpenAI gpt-4o-mini-tts 90.2 / Google Chirp3 HD 89.6 / ElevenLabs 89.0
- ElevenLabs v3 は表現力で高評価だが、24時間稼働では費用が突出する

### レイテンシ

対話型エージェントほどの即応性は不要(配信なので数百ms〜1秒の遅延は許容できる)が、参考値として:

- Cartesia Sonic 3.5: 約40ms(最速クラス)
- ElevenLabs Flash v2.5: 約75ms
- 一般に200ms未満は達成可能

**本件で重要なのはレイテンシより「実時間より速く生成し続けられるか」。** 24時間喋り続けるには、生成速度が再生速度を上回っている必要がある。

## AivisSpeech(最有力候補)

VOICEVOX API互換の音声合成エンジン。Linux + Docker でコマンド一発で起動でき、NVIDIA GPU にも対応する。

### ライセンス上の注意(重要)

**エンジン本体と音声モデルでライセンスが別。**

- **エンジン本体**: LGPL-3.0。「クレジット表記不要で、個人・法人・商用・非商用を問わず、自由にお使いいただけます」と明記
- **音声モデル**: AivisHub 上で配布され、**ACML / ACML-NC / CC0** のいずれか。**`ACML-NC` は非商用ライセンス**

配信は商用利用にあたるため、**声を選ぶ際に必ずモデルのライセンスを確認し、ACML-NC を避けること。** エンジンが商用OKでも、モデルがNCなら使えない。

### サーバー用途に関する公式の注意

開発元が次のように明記している。

> 一般的なPC上で1人で使うことを想定して設計されており、多くのリクエストを高速に捌く必要のあるAPIサーバー用途には最適化されていません

大規模なAPIサーバー用途には別製品(Citoras)を案内している。

**ただし本件の負荷特性はこの警告に当てはまらない可能性が高い。** 1キャラクターが逐次喋るだけで同時リクエストは発生せず、「多くのリクエストを高速に捌く」必要がない。必要なのは1本のストリームを実時間より速く生成し続けることだけ。

なお開発元は GPU サーバーでの生成速度・スケーラビリティにも根本的なボトルネックがあるとしている。一方で **ONNX Runtime により CPU 上で高速に動作する**とも記載があり、本件では GPU をレンダリングに専念させ TTS は CPU で回す構成が適合しうる。

## その他の選択肢

- **VOICEVOX**: ローカル動作、商用利用可、完全無料。AivisSpeech と API 互換なので差し替えやすい
- **Aivis Cloud API**: AivisSpeech のマネージド版。セルフホストの運用負担を避けたい場合の選択肢
- **Google Cloud TTS (Standard)**: 月$31程度と安価。品質は Neural 系に劣る

## 現時点の方針

**AivisSpeech のセルフホストを第一候補とする。** 日本語品質が最高評価で、エンジンが商用利用可、費用が実質ゼロ、VOICEVOX 互換なので差し替えも効く。

ただし採用確定には次の検証が必要。

## 未検証の事項

- **実時間より速く生成できるか**。サーバーCPU上での生成速度(リアルタイム係数)が本件の成否を分ける。実機での計測が必須
- 24時間連続稼働時の安定性(メモリリーク、長時間動作での劣化)
- 使用する音声モデルの選定とライセンス確認(ACML-NC を避ける)
- 生成音声から振幅を取り出し、レンダラーへ渡す経路の設計
- CPUでTTS、GPUでレンダリングを同一マシンで並行させたときのリソース競合
