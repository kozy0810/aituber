# TTS選定の調査結果をドキュメント化

対象Issue: #8

## 実装方針

TTSの調査結果を `docs/research/tts.md` にまとめる。既存の調査ドキュメント(`3d-model-generation-tools.md`、`headless-rendering-and-streaming.md`)と同じく、一次情報で確認できた事項と未検証の事項を分けて記載する。

### 記載の軸

**要件が緩和された経緯を最初に置く。** リップシンクが「音声振幅で板を動かす」方式に決まった結果、当初必須としていた音素・ビセーム出力が不要になった。この変更を知らずに読むと選定条件を誤解するため、冒頭で明示する。

**24時間稼働の経済性を主要な判断軸として扱う。** 従量課金のTTSは、連続発話という要件に対して費用が跳ね上がる。一方でレンダリング用サーバーはどのみち必要なため、TTSを同居させれば追加費用がほぼ発生しない。この非対称性が選定を左右するので、月額の概算比較を表で示す。

**ライセンスの罠を明記する。** AivisSpeech はエンジン本体が商用利用可だが、音声モデルは別ライセンス(ACML / ACML-NC / CC0)で、ACML-NC は非商用。配信は商用利用にあたるため、モデル選定を誤ると使えない。見落としやすく、かつ後から気づくと手戻りが大きいため独立した節にする。

**開発元の「サーバー用途に非最適」という注意書きを、本件の負荷特性と照らして評価する。** 警告をそのまま採用可否の結論にせず、「多数の同時リクエスト」を想定した注意であること、本件は1キャラクターの逐次発話で該当しない可能性が高いことを併記する。

### 結論の扱い

AivisSpeech のセルフホストを第一候補としつつ、**採用確定にはリアルタイム係数の実測が必要**である点を未検証事項として残す。実時間より速く生成できなければ24時間配信が成立しないため、ここが成否を分ける。
