# 実行環境の選択肢(ローカル vs クラウド)をドキュメント化

対象Issue: #10

## 実装方針

`docs/deployment-options.md` を新規作成する。既存の調査ドキュメントと違い、**人間が読んで意思決定するための文書**として書く。圧縮した箇条書きではなく、判断の根拠が追える文章にする。

### 書く内容の構成

**結論を最初に置く。** 開発はローカル、本番はMac miniが有力、ただし可用性が判断の分かれ目、という3点を冒頭で示す。詳細を読まなくても方針が掴めるようにする。

**GPUレンタルが不要になる技術的根拠を説明する。** クラウドGPUを検討していた主な動機がエンコードであったこと、Apple Silicon の VideoToolbox がその役割を代替すること、レンダリング負荷自体は元々軽いこと、node-webgl は macOS 向けプリビルトがあり Linux より導入が楽なこと。これらを順に示す。

**費用を具体的な数字で比較する。** 電気代は日本の電力単価(31円/kWh)で計算し、月額約560円という具体値を出す。クラウドとの差が約35倍であること、Mac mini の購入案が約5ヶ月で損益分岐することを明記する。

**ローカル運用の制約を正直に書く。** 費用だけ見るとローカルが圧倒的に有利なので、代わりに何を引き受けることになるのかを並べる。冷却(ファンレス機での連続稼働)、開発機との兼用不可、上り帯域、そして最大の弱点である可用性(停電・回線断・OSアップデート)。

**判断を先送りできることを示す。** 開発段階ではローカルを使い、本番構成は実際の動作を確認してから決められる。今の時点で確定させる必要がないという点を明示して、無用な意思決定コストを避ける。

### 既存ドキュメントとの整合

`docs/research/headless-rendering-and-streaming.md` はクラウドGPU前提で書かれており、そのままでは唯一の選択肢に読める。同ドキュメントのGPU費用の節に、ローカル運用という選択肢があることと本ドキュメントへの参照を追記する。
