# キャラクターモデル生成(参考画像 → リグ済みGLB)

配信用キャラクターを新規に作るとき、参考画像から**テクスチャとリグが付いた3Dモデル(GLB)**を作るまでの手順。この工程はキャラクター1体につき1回だけ発生する。

現時点では **Meshy の Web UI を手で操作する**のが唯一の経路。理由は後述の「なぜAPIを使わないか」を参照。

## この工程で何が得られ、何が得られないか

**得られるもの**: 体の動きを制御できるリグ。立ち姿勢の参考画像を使えば、体幹・頭・四肢・尾・耳に意味のある名前の付いたボーンと、歩行アニメーションが手に入る。`head` ボーンがあるため頷きや視線方向も制御できる。

**得られないもの**: 顎・口のボーンと、表情のブレンドシェイプ。**リップシンクはこの工程の出力だけでは実装できない**(詳細は後述の検証結果)。口の動きは別途、Blenderでの顎ボーン追加か、レンダラー側での頂点変形で用意する必要がある。

この前提を踏まえ、工程のゴールは「**体の動きを制御できるリグ付きGLBを得ること**」。テクスチャの美しさより、リグが正しく入っていることを優先する。

## なぜ手作業なのか(自動化の現状)

MeshyのリギングAPI(およびMCPの`meshy_rig`)は**人型(二足)専用**で、非人型に対応していない。`rig_type`に相当するパラメータ自体が存在しないため、**Meshy単独では四足のリギングはWeb UIでしか実行できない**。

この制約はMeshy自身のAIエージェントも認めている(四足リギングを依頼すると「現在のリギング機能は二足の人型スケルトン専用」と回答する)。

**さらに Meshy 6 Lite もWeb UI限定**で、API/MCP/エージェントからは `meshy-6` と `meshy-7` しか選べない。無料でダウンロードできる唯一のモデルがAPI経由では使えないため、**API経由では無料プランで成果物を取り出せない**。

| | Web UI | API / MCP / エージェント |
|---|---|---|
| 非人型のリギング | ○ | ✗ |
| Meshy 6 Lite(無料DL可) | ○ | ✗ |

このため、**無料プランで四足キャラクターを作る場合は全工程がWeb UIの手動操作になる**。キャラ登録は1体1回の作業なので現状はこれで足りる。Proプランを契約すれば、生成・テクスチャ・ダウンロードはAPI/MCPで自動化でき、手動が残るのはリギング工程だけになる。

**将来的に全工程を自動化する場合の選択肢**: TripoのRig APIは`rig_type`で7種の生物タイプ(四足・鳥・蛇・水生など)を指定でき、**プログラムから非人型のリギングができる唯一の選択肢**。入力は3Dモデル(GLB/FBX/OBJ/STL、150MBまで)なので、「Meshyで生成 → TripoでリギングというハイブリッドでE2E自動化が成立しうる。ただしTripo側の顎ボーンの有無は未確認で、2サービスの契約が必要になる。詳細は調査記録を参照。

なお Meshy の利用規約(Acceptable Use Policy)は「無許可の自動化・スクリプトによる一括アップロード」を禁じている。**Web UIを大量に自動操作してAPI課金を回避する使い方はしないこと。** 人が都度おこなう単発の操作の補助にとどめる。

## 手順

### 1. 参考画像を用意する

**ここが工程全体の成否を決める。** リグが通るかどうかは画像の姿勢でほぼ決まり、後の工程では取り返せない。

**1体だけが写った画像**にすること。front/side/back が1枚に並んだ三面図をそのまま入れると、被写体が並んだまま1つのメッシュになる(パンダが3頭つながったモデルができる)。

#### 手持ちの画像が条件を満たさない場合は作り直す

「四肢が体に密着している」「小道具が写っている」「背景が複雑」といった画像しかない場合、そのまま進めても**リギングで失敗する**。Meshyの画像生成機能で、条件を満たす参考画像を作り直すのが早い。

サイドバーの「画像」→ **画像参照に元のキャラクター画像を指定**(最大5枚)してプロンプトを書くと、**見た目を保ったまま姿勢だけ変えた画像**が得られる。コストは9クレジット/枚。

実際に使って有効だったプロンプトの要素:

```
A giant panda standing on all four legs in a neutral quadruped A-pose,
viewed from a three-quarter front angle. Full body clearly visible from
head to paws. All four legs are straight and clearly separated from the
torso with visible empty gaps between each leg and the body. Head held
level facing forward, mouth closed. Plain flat light gray studio
background, completely empty. No plants, no bowl, no pot, no flowers,
no rocks, no ground decoration, no props of any kind. Even neutral
lighting, no deep shadows. Character reference sheet style for 3D modeling.
```

要点は「四足で立つ」「四肢と胴の間に隙間が見える」「全身が写る」「無地の背景」「小道具を名指しで否定する」。小道具は `no props` だけでは残ることがあるため、元画像に写っているもの(鉢・花・岩など)を個別に列挙して打ち消す。

四足動物なら**アスペクト比は16:9**が収まりがよい。

#### 口は目立たせない(後から直せない)

リップシンクは、3Dモデルの口を動かすのではなく**別の板を口の位置に重ねて**表現する(生成メッシュには口の開口部が作られないため。詳細は `docs/research/3d-model-generation-tools.md`)。

このとき、テクスチャに濃い口が描かれていると**重ねた口と二重に見える**。これは画像生成の時点で決まり、モデル生成後には直せない。

プロンプトで口を控えめに指定しておくこと。`mouth closed` に加えて、口元の陰影や線を強調しない旨を添える:

```
mouth closed, neutral relaxed muzzle with no pronounced mouth line,
no visible teeth, no open jaw
```

三面図なら先に切り出す:

```bash
scripts/split_turnaround.sh <三面図の画像> <出力先ディレクトリ>
```

出力された画像は**必ず目視で確認する**。ラベルや隣のパネルが写り込んでいたらスクリプト内の `MT` / `INSET` を調整して再実行する。

画像を選ぶ際の重要な観点:

- **背景と小道具はメッシュに取り込まれる。** 鉢植え・台座・草などが写っていると、キャラクターと一体化したメッシュになる。可能なら被写体だけを切り抜いた画像を使う
- **四肢が体から離れた姿勢が望ましい。** Meshyのリギングは「Tポーズに近く、四肢と体に明確な隙間がある」形状を推奨し、「四肢が隠れている」形状を非推奨としている。座って手足が体に密着した画像だと、マーカーの自動配置が破綻して手直しが必要になる

### 2. モデルのバージョンを選ぶ(ここが分岐点)

Meshyワークスペースの左パネル上部でAIモデルを選択する。**この選択がダウンロードの可否を決める**ので最初に決めること。

| | Meshy 6 Lite | Meshy 6 / Meshy 7 |
|---|---|---|
| 無料プランでのダウンロード | **○ 月10回** | **✗ 有料プラン必須** |
| 生成コスト | 10クレジット | 20クレジット |
| メッシュの重さ(実測) | **約19万面** | 約776万面 |
| テクスチャ生成時間 | 約30秒 | 約2分 |

**開発・検証では Meshy 6 Lite を選ぶ。** 無料でダウンロードできるうえ、メッシュが40分の1に軽く、リアルタイム描画にはむしろ適している。Meshy 7 の精細さはこの用途では過剰で、かえってポリゴン削減の手間が増える。

本番で品質を上げたくなった段階で Meshy 7 + 有料プランへ移行する。

### 3. ホワイトモデルを生成する

画像をアップロードして「生成する」。ここで出てくるのは**形状だけの白いモデル**。色は付かない。これは仕様であって失敗ではない。

Meshy 6 Lite ではここで**ポーズ指定(Aポーズ/Tポーズ、有料機能)**が選べる。使えるなら指定した方がよい。前述のリグ推奨形状を生成時点で満たせるため、マーカー調整の手間が減る。

### 4. テクスチャを適用する

下部ツールバーの「テクスチャ」から実行する。**ここで参考画像をもう一度アップロードする必要がある**(色の根拠として使われるため)。手順1の画像をそのまま渡す。

コストは10クレジット。PBRマップの生成はオンのままでよい。

### 5. リギングする(この工程が本番)

「アニメート」(左サイドバー)またはツールバー右端の走る人アイコンから、モデルを選んで「リギング」。

**キャラクタータイプの選択:**

| 選択肢 | 使いどころ | アニメーションライブラリ |
|---|---|---|
| ヒューマノイド | 人型 | 使える |
| 四足歩行イヌ科 | **四足で立った姿勢**の動物 | 使える |
| **スマートリグ (Beta)** | **上記で失敗する体型全般**(座り姿勢、鹿・タコ・蜘蛛など) | **使えない** |

#### 四足歩行イヌ科は姿勢が合わないと「失敗する」

リギング画面の「推奨されないモデル」の警告は、品質が落ちるという意味ではない。**実際にジョブが失敗する。**

同じキャラクターで姿勢だけを変えて比較した実測結果:

| 参考画像の姿勢 | 四足歩行イヌ科 | メッシュ |
|---|---|---|
| 座り・四肢が体に密着・小道具つき | **失敗**(「リギングに失敗しました」) | 193,446面 |
| **立ち・四肢が離れている・小道具なし** | **成功** | **61,622面** |

姿勢を直すだけで結果が反転する。しかも小道具が消えた分メッシュも3分の1に軽くなる。**手順1の画像要件を満たすことが、この工程の成否をほぼ決める。**

立ち姿勢に直せない事情がある場合のみ、スマートリグを使う(座り姿勢でも成功する)。ただし**スマートリグの出力には顎ボーンが含まれない**ため、リップシンクが必要なら立ち姿勢で四足歩行イヌ科を通すこと。

#### スマートリグを選んだ場合の違い

- **マーカー配置の工程がない。** 選択してすぐ実行される(手動調整の余地もない)
- **プリセットのアニメーションライブラリが使えない**(「Smart Rigモデルはまだアニメーションライブラリに対応していません」)。ただし本プロジェクトはボーンをプログラムから直接制御するため、この制約は問題にならない

#### 四足歩行イヌ科を選んだ場合(立ち姿勢のとき)

**向きの調整**: キャラクターが**画面の左側を向いている**状態にする。

**マーカー配置**: 顎・肩・前脚・前膝・前足・腰・臀部・尾・後脚・後膝・後足の11箇所。

- 自動配置される。姿勢がテンプレートから外れるとマーカーがメッシュ外の空間に浮く
- **マーカーはドラッグで手動調整できる**
- 最低限、**顎のマーカーは必ず正しい位置に置くこと**。リップシンクの根拠になる唯一のボーンであり、ここがずれると口が動かない

### 6. ダウンロードして検証する

アセット一覧でモデルの「…」メニュー →「ダウンロード」。設定項目:

- **フォーマット**: `glb`
- **リグドキャラクター**: **既定はオフ。必ずオンにする。** オフのままダウンロードすると**骨格が入っていないメッシュだけ**が落ちてくる。この工程で最も見落としやすい罠
- **スケルトンテンプレート**: スマートリグ経由の場合のみ表示され、既定は `Mixamo`
- ダウンロードボタンのバッジ(`x10` など)が**今月の無料ダウンロード残回数**

ダウンロードしたGLBの中身を検証する:

```bash
python3 scripts/inspect_glb.py <path-to.glb>
```

このスクリプトが判定するのは:

- ボーンの一覧と、それぞれのバインドポーズ位置
- 顎・口まわりのボーンの有無
- 頭・首ボーンの有無(視線制御に使う)
- モーフターゲット(ブレンドシェイプ)の数
- 頂点数・三角形数(リアルタイム描画に耐えるか)
- **口のアンカー座標**(リップシンク用の板を取り付ける位置)。顔の向きを脚ボーンから判定し、headボーン近傍の最前方頂点を鼻先として導出する。相対位置のXが50%付近にあれば妥当

**顎ボーンが検出されなければ、その工程はやり直す。** リップシンクが成立しないモデルを配信システムに渡しても意味がない。

スクリプトはボーン名だけでなく**バインドポーズでの位置**も出力する。スマートリグの出力はボーン名が `Bone_000` のような無名連番になるため、名前では判定できない。その場合は位置から読み取る。

- 左右対称に同じ高さで並ぶ対 → 耳や目
- 口・顎は**顔の前面(Z)かつ頭の中心より下**にあるはず
- 該当がなければ顎ボーンは生成されていない

### 検証済みの事実: どの経路でも顎ボーンは得られない

両方のリグ経路で実際にGLBを書き出して解析した結果。

| リグ経路 | ボーン名 | 顎ボーン |
|---|---|---|
| スマートリグ | `Bone_000`〜 の無名連番 | **なし** |
| 四足歩行イヌ科(立ち姿勢) | 意味のある名前(下記) | **なし** |

立ち姿勢で得られる27ボーンの構成:

```
Hips
├ chest → head → headend / earend / R_earend
├ tail → tailstart → tail1 → tail2 → tail3
├ backleg → backleg0 → backleg1 → backleg2   (左右)
└ frontleg → frontleg0 → frontleg1 → frontleg2 (左右)
```

歩行アニメーションも同梱され、**体の動きとしては実用的なリグ**。だが頭部は `head` / `headend` / 左右の `earend` だけで、**顎・口のボーンがない**。

**リギングUIで「顎」マーカーを配置しても、独立した顎ボーンは書き出されない。** 顎マーカーは頭ボーンの位置決めに使われているだけ。Meshyのリグは歩行アニメーションが目的で、表情・口の動きは設計対象外。

モーフターゲットも両経路とも0個。

### さらに根本的: メッシュに口の立体がない

顎ボーンの不在以上に効いてくる制約。**生成メッシュには口の開口部が存在しない。**

顔の正中線に沿って前面の位置を測ると、鼻先から額まで滑らかな凸曲線になり、口にあたる凹みが現れない。口を閉じた写真から生成しているため当然だが、結果として**ボーンを足しても頂点を動かしても「口が開く」表現にはならない**(開口部のない顔の下半分が伸びるだけ)。

参考画像が口を閉じている限り、この制約は避けられない。リップシンクが必要な場合は、モデル生成とは別のレイヤーで解決する(2Dの口を合成する、口を開けた画像から生成する、など)。方式の検討は `docs/research/3d-model-generation-tools.md` を参照。

**この制約は口の動きに限った話。** 体の動き(歩く・向きを変える・頷く・耳を動かす)は得られたリグで問題なく制御できる。

## 無料プランで踏む制約(実測)

- **同時実行タスクは1つだけ。** テクスチャ生成中にリギングを始めようとすると課金モーダルが出る。順番に実行する
- 待機列の優先度が低く、処理が数分停滞することがある。急ぎのときは有料プランを検討する
- ライセンスは **CC BY 4.0**。商用利用は可能だが**帰属表示が必須**(「Model created with Meshy – CC BY 4.0 License」)。帰属表示を外したい場合は有料プランの「プライベート」ライセンスを選ぶ
- ログイン時のデイリーチェックインでクレジットが加算される(第1日+30〜第5日+100&ダウンロード1回)

## 生成後に残る課題

この工程の出力をそのまま配信に使えるとは限らない。次を確認する。

- **不要物の混入**: 背景や小道具がメッシュに含まれていないか。含まれていたら画像を切り抜き直して再生成する
- **ポリゴン数**: Meshy 6 Lite でも約19万面ある。リアルタイム描画の一般的な目安(1万〜10万)を超えるため、リメッシュでの削減を検討する
- **リグの妥当性**: 顎以外のボーンが破綻していても、配信で使うのが上半身中心なら許容できる場合がある。用途に照らして判断する
