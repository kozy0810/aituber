# キャラクターモデル生成(参考画像 → リグ済みGLB)

配信用キャラクターを新規に作るとき、参考画像から**テクスチャとリグが付いた3Dモデル(GLB)**を作るまでの手順。この工程はキャラクター1体につき1回だけ発生する。

現時点では **Meshy の Web UI を手で操作する**のが唯一の経路。理由は後述の「なぜAPIを使わないか」を参照。

## 前提となる設計判断(変更する前に読むこと)

このプロジェクトでは、リップシンクを**顎ボーンの回転を音声振幅に連動させる方式**で実装する。ビセーム(口の形のブレンドシェイプ)は使わない。自動生成ツールがビセームを出力しないためで、四足リグに含まれる**顎ボーン1本**があれば成立することを実機で確認済み。

したがってこの工程のゴールは「**顎ボーンを含むリグが付いたGLBを得ること**」。テクスチャの美しさより、リグが正しく入っていることを優先する。

## なぜ手作業なのか(自動化の現状)

MeshyのリギングAPI(およびMCPの`meshy_rig`)は**人型(二足)専用**で、非人型に対応していない。`rig_type`に相当するパラメータ自体が存在しないため、**Meshy単独では四足のリギングはWeb UIでしか実行できない**。

生成・テクスチャ・ダウンロードはMeshyのAPI/MCP(Proプラン以上)で自動化できるので、手動が残るのはリギング工程だけ。キャラ登録は1体1回の作業なので、現状はこの運用で足りる。

**将来的に全工程を自動化する場合の選択肢**: TripoのRig APIは`rig_type`で7種の生物タイプ(四足・鳥・蛇・水生など)を指定でき、**プログラムから非人型のリギングができる唯一の選択肢**。入力は3Dモデル(GLB/FBX/OBJ/STL、150MBまで)なので、「Meshyで生成 → TripoでリギングというハイブリッドでE2E自動化が成立しうる。ただしTripo側の顎ボーンの有無は未確認で、2サービスの契約が必要になる。詳細は調査記録を参照。

なお Meshy の利用規約(Acceptable Use Policy)は「無許可の自動化・スクリプトによる一括アップロード」を禁じている。**Web UIを大量に自動操作してAPI課金を回避する使い方はしないこと。** 人が都度おこなう単発の操作の補助にとどめる。

## 手順

### 1. 参考画像を用意する

**1体だけが写った画像**にすること。front/side/back が1枚に並んだ三面図をそのまま入れると、被写体が並んだまま1つのメッシュになる(パンダが3頭つながったモデルができる)。

三面図なら先に切り出す:

```bash
scripts/split_turnaround.sh <三面図の画像> <出力先ディレクトリ>
```

出力された画像は**必ず目視で確認する**。ラベルや隣のパネルが写り込んでいたらスクリプト内の `MT` / `INSET` を調整して再実行する。

画像を選ぶ際の重要な観点:

- **背景と小道具はメッシュに取り込まれる。** 鉢植え・台座・草などが写っていると、キャラクターと一体化したメッシュになる。可能なら被写体だけを切り抜いた画像を使う
- **四肢が体から離れた姿勢が望ましい。** Meshyのリギングは「Tポーズに近く、四肢と体に明確な隙間がある」形状を推奨し、「四肢が隠れている」形状を非推奨としている。座って手足が体に密着した画像だと、マーカーの自動配置が破綻して手直しが必要になる

### 2. モデルのバージョンを選ぶ(ここが分岐点)

Meshyワークスペースの左パネル上部でAIモデルを選択する。**この選択がダウンロードの可否を決める**ので最初に決めること。

| | Meshy 6 Lite | Meshy 6 / Meshy 7 |
|---|---|---|
| 無料プランでのダウンロード | **○ 月10回** | **✗ 有料プラン必須** |
| 生成コスト | 10クレジット | 20クレジット |
| メッシュの重さ(実測) | **約19万面** | 約776万面 |
| テクスチャ生成時間 | 約30秒 | 約2分 |

**開発・検証では Meshy 6 Lite を選ぶ。** 無料でダウンロードできるうえ、メッシュが40分の1に軽く、リアルタイム描画にはむしろ適している。Meshy 7 の精細さはこの用途では過剰で、かえってポリゴン削減の手間が増える。

本番で品質を上げたくなった段階で Meshy 7 + 有料プランへ移行する。

### 3. ホワイトモデルを生成する

画像をアップロードして「生成する」。ここで出てくるのは**形状だけの白いモデル**。色は付かない。これは仕様であって失敗ではない。

Meshy 6 Lite ではここで**ポーズ指定(Aポーズ/Tポーズ、有料機能)**が選べる。使えるなら指定した方がよい。前述のリグ推奨形状を生成時点で満たせるため、マーカー調整の手間が減る。

### 4. テクスチャを適用する

下部ツールバーの「テクスチャ」から実行する。**ここで参考画像をもう一度アップロードする必要がある**(色の根拠として使われるため)。手順1の画像をそのまま渡す。

コストは10クレジット。PBRマップの生成はオンのままでよい。

### 5. リギングする(この工程が本番)

「アニメート」(左サイドバー)またはツールバー右端の走る人アイコンから、モデルを選んで「リギング」。

**キャラクタータイプの選択:**

| 選択肢 | 使いどころ | アニメーションライブラリ |
|---|---|---|
| ヒューマノイド | 人型 | 使える |
| 四足歩行イヌ科 | **四足で立った姿勢**の動物 | 使える |
| **スマートリグ (Beta)** | **上記で失敗する体型全般**(座り姿勢、鹿・タコ・蜘蛛など) | **使えない** |

#### 四足歩行イヌ科は姿勢が合わないと「失敗する」

リギング画面の「推奨されないモデル」の警告は、品質が落ちるという意味ではない。**実際にジョブが失敗する。**

実測: 座った姿勢のパンダ(四肢が体に密着)に「四足歩行イヌ科」を適用したところ、マーカーを手動調整したうえで実行しても**「リギングに失敗しました」**で終了した。このテンプレートは**四足で立った動物**を前提にしている。

**座った姿勢・直立姿勢など、立った四足動物でない場合は最初からスマートリグを選ぶ。** 同じモデルでスマートリグは成功した。

#### スマートリグを選んだ場合の違い

- **マーカー配置の工程がない。** 選択してすぐ実行される(手動調整の余地もない)
- **プリセットのアニメーションライブラリが使えない**(「Smart Rigモデルはまだアニメーションライブラリに対応していません」)。ただし本プロジェクトはボーンをプログラムから直接制御するため、この制約は問題にならない

#### 四足歩行イヌ科を選んだ場合(立ち姿勢のとき)

**向きの調整**: キャラクターが**画面の左側を向いている**状態にする。

**マーカー配置**: 顎・肩・前脚・前膝・前足・腰・臀部・尾・後脚・後膝・後足の11箇所。

- 自動配置される。姿勢がテンプレートから外れるとマーカーがメッシュ外の空間に浮く
- **マーカーはドラッグで手動調整できる**
- 最低限、**顎のマーカーは必ず正しい位置に置くこと**。リップシンクの根拠になる唯一のボーンであり、ここがずれると口が動かない

### 6. ダウンロードして検証する

アセット一覧でモデルの「…」メニュー →「ダウンロード」。設定項目:

- **フォーマット**: `glb`
- **スケルトンテンプレート**: `Mixamo`(既定)。ボーン名が `mixamorig:` 接頭辞付きになる
- **リグドキャラクター**: オン
- ダウンロードボタンのバッジ(`x10` など)が**今月の無料ダウンロード残回数**

ダウンロードしたGLBの中身を検証する:

```bash
python3 scripts/inspect_glb.py <path-to.glb>
```

このスクリプトが判定するのは:

- ボーンの一覧
- **顎・口まわりのボーンの有無**(最重要)
- 頭・首ボーンの有無(視線制御に使う)
- モーフターゲット(ブレンドシェイプ)の数
- 頂点数・三角形数(リアルタイム描画に耐えるか)

**顎ボーンが検出されなければ、その工程はやり直す。** リップシンクが成立しないモデルを配信システムに渡しても意味がない。

スクリプトはボーン名だけでなく**バインドポーズでの位置**も出力する。スマートリグの出力はボーン名が `Bone_000` のような無名連番になるため、名前では判定できない。その場合は位置から読み取る。

- 左右対称に同じ高さで並ぶ対 → 耳や目
- 口・顎は**顔の前面(Z)かつ頭の中心より下**にあるはず
- 該当がなければ顎ボーンは生成されていない

### 実測結果: スマートリグの出力には顎ボーンがない

座り姿勢のパンダをスマートリグでリギングし、出力GLBを解析した結果:

- ボーンは15本。すべて `Bone_000` 〜 `Bone_014` の**無名連番**
- 構造は解剖学的には妥当(体幹 → 頭 → 左右対称の耳、および脚の鎖)
- **顎・口に相当するボーンは存在しない**。頭部にあるのは頭の中心1本と左右の耳のみ
- モーフターゲットも0個

**つまりスマートリグ経由では、顎ボーン方式のリップシンクが成立しない。**

顎ボーンを得るには「四足歩行イヌ科」(マーカー一覧に「顎」がある)を通す必要があり、そのためには**四肢が体から離れた立ち姿勢の参考画像**が要る。手順1の画像要件が、ここで効いてくる。

### 顎ボーンが得られなかった場合の選択肢

1. **参考画像を作り直して「四足歩行イヌ科」で再実行**(推奨)。立ち姿勢・四肢を離す・小道具を除去する
2. Blenderで顎ボーンを手動追加する(キャラ1体につき1回の作業)
3. 口まわりの頂点をプログラムで直接変形させる(ボーンを使わない)
4. 体型アーキタイプに顔リグを作り込む方式へ切り替える

## 無料プランで踏む制約(実測)

- **同時実行タスクは1つだけ。** テクスチャ生成中にリギングを始めようとすると課金モーダルが出る。順番に実行する
- 待機列の優先度が低く、処理が数分停滞することがある。急ぎのときは有料プランを検討する
- ライセンスは **CC BY 4.0**。商用利用は可能だが**帰属表示が必須**(「Model created with Meshy – CC BY 4.0 License」)。帰属表示を外したい場合は有料プランの「プライベート」ライセンスを選ぶ
- ログイン時のデイリーチェックインでクレジットが加算される(第1日+30〜第5日+100&ダウンロード1回)

## 生成後に残る課題

この工程の出力をそのまま配信に使えるとは限らない。次を確認する。

- **不要物の混入**: 背景や小道具がメッシュに含まれていないか。含まれていたら画像を切り抜き直して再生成する
- **ポリゴン数**: Meshy 6 Lite でも約19万面ある。リアルタイム描画の一般的な目安(1万〜10万)を超えるため、リメッシュでの削減を検討する
- **リグの妥当性**: 顎以外のボーンが破綻していても、配信で使うのが上半身中心なら許容できる場合がある。用途に照らして判断する
